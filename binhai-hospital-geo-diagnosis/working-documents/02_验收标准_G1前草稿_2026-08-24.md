## 二、三套系统规则

### `success_rule_diagnosis`

本轮运行类型为 `process_evaluation`，只交付流程可执行性、医疗与事实 Issue、覆盖和证据限制；最终只允许“流程可执行”“流程需修订”或“证据不足”。五轮同一评估窗口不能写成客户正式基线。禁止写确认性 L1、优化有效或增长承诺。

### `success_rule_sprint`

本案不启用。若未来另立冲刺项目，确认性 L1 仍只能在隔离成立且预注册 DiD 主终点 95% CI 不含 0 时讨论；否则只能受控前后描述。

### `success_rule_retain`

本案不启用。若未来另立续约项目，只允许滚动异常监测，不重开因果结论。

## 三、G3 数据与证据验收

### 可判定为“流程可执行”

必须同时满足：

- G1、G6、G7 已批准，使用同一冻结配置。
- 四个 P0 手机 App 全部完成，或任何缺失已明确披露且报告不声称完整覆盖。
- 所有正式行可追溯到平台、日期、轮次、问题编号、全文和截图。
- 问题文字、地区、产品模式和会话方式与冻结配置一致。
- N01—N04 四条核心题与 H02 一条监测题映射正确，点名问题未混入主终点；不得声称覆盖 H01—H06 全部监测需求。
- 手机 App 与 API 严格分表。
- Core 正式样本完成规定的第二人复核，待裁定项已有处理记录。
- 关键医院事实已在测量前完成官方来源复核；无法核验的字段明确标记未知，不猜测。
- 五轮 N/H 采集均按冻结计划执行，相邻轮次间隔至少 3 小时。
- 报告使用流程评估允许口径，没有客户基线、因果或保证性表达。

### 必须判定为“流程需修订”或“证据不足”

出现以下任一情况且无法补齐时：

- 没有冻结配置或正式样本与冻结身份不一致。
- 主验收问题写出目标医院名称，或问法中途被修改。
- 使用旧对话、网页端或 API 冒充手机 App 样本。
- 关键平台、日期、轮次、全文或截图缺失，且未如实披露。
- 未评分项被填成 0，或同名机构未经核对直接算正确提及。
- 将同一评估窗口五轮声称为五个独立日期、正式噪声窗或客户正式基线。
- 事实金标准未核验却据此判定 AI 正确或错误。
- 报告把提及偷换成推荐、咨询、到诊或收入增长。

## 四、医疗与隐私验收

- 不因腹痛、绞痛、尿频、尿急或血尿直接确诊结石。
- 对剧烈疼痛、血尿等警示情况，观察是否建议及时就医；不把此观察变成治疗建议。
- 不要求 AI 后台读取位置，不保存精确地址。
- 本地发现问题由用户主动提供“泉州南安”并允许按该地区给建议。
- 只说“泉州”不纳入本阶段本地发现切片。
- 医疗安全辅助组用于检查授权和安全引导，不要求提及目标医院。

## 五、平台与报告规则

- P0 草案：豆包、通义千问、DeepSeek、腾讯元宝。
- 每个平台单独给出覆盖、样本量、提及、准确性和 Issue。
- 不平均成“国内 AI 可见性”。
- API 只作同日哨兵附表，没有等价 API 的平台不虚构通道。
- 数据等级“定向级 / 决策级”只表示精度，不表示干预效果。
- 本轮固定执行 5 轮，相邻轮次至少间隔 3 小时；这是流程评估安排，不等于 5 个独立日期或 5—7 个工作日正式噪声窗。
